# System Design — Real-Time Voice Chatbot Engine

This document details the system design, communication protocols, state management, and file structure of the Real-Time TTS & STT Speech Engine.

---

## System Architecture

```mermaid
sequenceDiagram
    autonumber
    actor User
    participant Client as React Client (VoiceChat)
    participant Rec as AudioRecorder
    participant Play as AudioPlayer
    participant Backend as FastAPI Server (main.py)
    participant STT as Sarvam STT API
    participant LLM as Google Gemini API
    participant TTS as Sarvam TTS WebSocket

    %% User Initiates Conversation
    User->>Client: Clicks mic button (State: ready)
    Client->>Rec: Start recording
    Rec-->>Client: Capturing Float32 microphone data
    User->>Client: Stops speaking / Clicks mic button
    Client->>Rec: Stop recording & extract PCM16 buffer
    Rec-->>Client: Returns ArrayBuffer (Int16 PCM) + sampleRate

    %% WebSocket Transmission
    Client->>Backend: WS "audio.start" {sampleRate: 48000}
    Client->>Backend: WS binary (Int16 PCM buffer)
    Client->>Backend: WS "audio.end"
    Note over Client,Backend: State: processing

    %% Backend Pipeline Orchestration
    Backend->>Backend: Convert raw PCM16 to WAV (prepends 44-byte header)
    Backend->>STT: HTTP POST /speech-to-text (Saaras Model)
    STT-->>Backend: Returns transcription JSON
    Backend->>Client: WS "stt.result" {text: "..."}

    %% Concurrent LLM & TTS
    par LLM Streaming to Backend
        Backend->>LLM: Generate content stream (Gemini Flash)
        LLM-->>Backend: Yield tokens incrementally
        Backend->>Client: WS "llm.token" {text: "token"}
        Backend->>Backend: Buffer text until sentence boundaries (.!?।;:)
    and TTS Streaming to Client
        Backend->>TTS: WS Config message (WAV output format)
        Backend->>TTS: WS Text message (per chunked sentence)
        TTS-->>Backend: Yield base64 WAV chunks
        Backend->>Backend: Strip WAV header (extract raw Int16 PCM)
        Backend->>Client: WS binary (raw PCM16 audio chunk)
    end

    %% Completion
    LLM-->>Backend: LLM Done
    Backend->>Client: WS "llm.done" {text: "full response"}
    TTS-->>Backend: Event final
    Backend->>Client: WS "tts.done"
    Note over Client,Play: Playback finishes playing out
    Client-->>User: Playback complete (State: ready)
```

## WebSocket Protocol Specification

The client and server communicate bidirectionally over a single WebSocket connection at `/ws/voice`.

### 1. Client → Server Messages

#### Control Messages (JSON)
* **Start Recording**: Sent when the user starts speaking.
  ```json
  {
    "type": "audio.start",
    "sampleRate": 48000
  }
  ```
* **Stop Recording**: Sent when the user stops speaking.
  ```json
  {
    "type": "audio.end"
  }
  ```
* **Interrupt (Barge-in)**: Sent when the user interrupts the assistant's speech.
  ```json
  {
    "type": "interrupt"
  }
  ```
* **Clear History**: Clear current conversation context on the server.
  ```json
  {
    "type": "clear_history"
  }
  ```
* **Keepalive Ping**: Prevent WebSocket timeouts.
  ```json
  {
    "type": "ping"
  }
  ```

#### Data Messages (Binary)
* **Raw Audio**: Raw Int16 mono PCM audio payload, sent immediately after `audio.start`.

---

### 2. Server → Client Messages

#### Status & Context (JSON)
* **Pipeline Processing Stage**: Indicates active backend tasks.
  ```json
  {
    "type": "processing",
    "stage": "stt" // or "llm"
  }
  ```
* **Transcription Result**: Final text transcribed from the user's audio.
  ```json
  {
    "type": "stt.result",
    "text": "Hello, how are you?"
  }
  ```
* **LLM Output Token**: Text tokens as they are generated by the model.
  ```json
  {
    "type": "llm.token",
    "text": " Hello"
  }
  ```
* **LLM Processing Done**: The complete generated response text.
  ```json
  {
    "type": "llm.done",
    "text": "Hello! I am doing well, how can I help you today?"
  }
  ```
* **TTS Synthesis Initiated**: Indicates speech audio is commencing.
  ```json
  {
    "type": "tts.start",
    "sampleRate": 22050
  }
  ```
* **TTS Synthesis Done**: Signals that all synthesized audio has been transmitted.
  ```json
  {
    "type": "tts.done"
  }
  ```
* **Interrupted Confirmation**: Confirms server-side pipeline cancellation.
  ```json
  {
    "type": "interrupted"
  }
  ```
* **Error Report**: Indicates a failure at any stage of the pipeline.
  ```json
  {
    "type": "error",
    "message": "Speech recognition failed: ..."
  }
  ```

#### Audio Content (Binary)
* **Raw Audio Chunks**: Mono Int16 PCM (usually at 22050 Hz) stripped of container/header metadata, ready to play.

## State Machine (Frontend Client)

The React client transitions through four states to maintain a smooth user experience:

```
        ┌──────────────┐
        │    READY     │◄───────────────────┐
        └──────┬───────┘                    │
               │                            │
               │ (Start Recording)          │ (TTS Done / Finished Playing)
               ▼                            │
        ┌──────────────┐                    │
        │  RECORDING   │                    │
        └──────┬───────┘                    │
               │                            │
               │ (Stop Recording / STT)     │
               ▼                            │
        ┌──────────────┐             ┌──────┴──────┐
        │  PROCESSING  │────────────►│  SPEAKING   │
        └──────────────┘ (TTS Start) └─────────────┘
               ▲                            │
               └────────────────────────────┘
                   (Interrupt / Mic Press)
```

1. **`ready`**: Default state. Microphone is inactive, speaker is idle. UI prompts the user to tap and speak.
2. **`recording`**: Microphone stream is active, slicing Float32 samples, downsampling to browser's native sample rate, and buffering Int16 PCM blocks.
3. **`processing`**: Recording has ended. Client transmits the audio payload. Server is orchestrating STT and LLM generation.
4. **`speaking`**: Backend has begun streaming audio chunks. The client-side Jitter Buffer pre-buffers chunks, schedules them on the Web Audio context timeline, and renders the streaming text in real time.
